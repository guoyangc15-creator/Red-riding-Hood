# 小红帽 V3｜技术方案

## 现有项目与复用

基于仓库 `guoyangc15-creator/Red-riding-Hood` 当前主页面进行静态审计，基础文件 blob SHA：`7da90254117033848ceefb2dc6851be40122dc04`。根目录旧版保持不变，V3 作为 `/v3/index.html` 独立入口，避免改变原用户已保存的 TikTok 项目。Git 历史可恢复旧版本，交付包另含旧页面备份。

保留原品牌色、基础表单/面板样式体系、四步选人流程。复用或适配原 `esc`、`clamp`、`overlap`、`audienceTags`、维度贡献加权、未知报价处理、名单预算校验、按达人编辑草稿及 Blob 导出机制。新增工作台、笔记数据模型、诊断状态与推广计划。原英文模板、美元估算、公开美国达人没有映射成小红书数据。

## 运行方式

单个 HTML 包含全部 CSS、JavaScript、案例数据及原创 SVG。无运行时依赖、API key、数据库或构建要求。可以双击打开；本地文件协议可能限制持久化或剪贴板，页面提供提示和手动复制兜底。GitHub Pages 使用 `/v3/`，刷新仍可加载。文档链接需同时保留 docs 目录。

测试使用 Node + jsdom（仅开发依赖，网站运行不需要）。运行：`NODE_PATH=<jsdom所在node_modules> node tests/regression.cjs`。

## 数据模型

- `state.form`：项目、品牌、产品、需求、目标、用途、四项费用。
- `creators`：6位虚构达人，受众/内容标签，示例标注分、报价、地域/档期/权利的三态值。
- `state.selected`：新合作拟邀约名单，不表示合作已发生。
- `state.edits`：按达人ID保存中文邀约与 Brief，材料重建前二次确认。
- `state.assets`：3条模拟合作内容；自身品牌/产品归属、类型、脚本/图片文案、人工事实标注、表现、权利和内容版本。
- `state.revision` 与 `asset.version`：需求与内容版本；已查看诊断关联二者。
- `state.plans`：每条内容的媒体预算、授权费、周期、指标、停止条件、独立编辑正文、就绪/过时状态。
- localStorage key `redhood-xhs-v3.1`，与旧版 `redhood-v3-public` 隔离。浏览器本地保存不是云同步。

## 判定与状态

`eligibility → scoreCreator → rank`：已确认不符合则排除；未知条件保留但置于待确认组；分数只比较当前样例。权重与贡献在卡片可查。

`diagnose` 读取人工事实标注 `signals`，结合项目目标、受众、归属与证据有效性。规则结果不是案例 ID 对应的固定广告效果分。`readiness` 独立检查使用权/期限/音乐/购买路径。`planErrors` 再检查日期、预算、多个已核对计划的合计及本版诊断状态。

修改需求使计划过时并取消就绪；修改单条内容只使该条计划过时。正文编辑保留。每次渲染重新检查已核对计划，过期或条件改变即取消就绪标记。最终按钮再验证，不能仅靠按钮外观作为校验。

## 输出与安全

`materialText` 收集每位已选达人的最后编辑内容；单人导出不包含其他达人。`planText` 包含当前结构化条件与最后编辑正文，说明冲突需人工核对。下载使用 UTF-8 Markdown Blob；复制失败展示可选择文本。

用户内容经 `esc` 转义后进入模板；金额采用 Number 并检查有限数值/范围；无 fetch、第三方脚本或用户信息外发。公开研究链接只在用户主动打开时访问。

## 扩展边界

未来模型服务应独立提供 `extractBrief / summarizeEvidence / draftMaterials` 类型接口，返回事实来源与未知字段，由规则层复核。当前未实现这些 API，不向浏览器埋密钥。真实数据接入需单独获得授权，并建立平台指标口径、费用与权利适配器。

状态校验为客户端演示逻辑，不用于生产计费、真实授权或资金安全。当前没有自动广告发布能力。
